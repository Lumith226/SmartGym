## Quy tắc thực thi

- CI chạy unit, schema/contract và integration theo service. Integration dùng PostgreSQL, RabbitMQ, object store và SMTP thử nghiệm theo quyền riêng. Dùng fixture cho service dependencies khi unit test. Cổng E2E dùng bản build thật, Catalog có snapshot SmartGym đã duyệt và AI dùng model/runtime đã xác minh.
- Test contract xác minh auth, `operationId`, schema request/response, lỗi, headers và event. Test consumer/provider cùng một phiên bản đang dùng và phiên bản sau thay đổi tương thích. Với event, thử lặp, thứ tự đảo, DLQ và replay. Với mutation, chạy ít nhất hai request song song và kiểm tra database của đúng owner.
- Chuẩn bị tài khoản USER A/B và ADMIN test, bài `bodyweight_squat`, dữ liệu hai múi giờ, fake clock cho nhắc lịch, clip đã duyệt và bộ câu hỏi tiếng Việt đã giữ lại. Khôi phục môi trường sau mỗi scenario. Log bằng correlation ID, bỏ dữ liệu nhạy cảm.
- Chạy a11y tự động kết hợp test bàn phím, viewport 320/640/1024/1440 CSS px và zoom 200%. Chạy performance trên môi trường định danh với profile ở [Operations](../guides/OPERATIONS.md). Chạy AI theo [AI integration](../design/AI_INTEGRATION.md). Security theo [Security](../design/SECURITY.md).
- Ghi lệnh, commit/artifact, môi trường, dữ liệu, thời điểm, kết quả và bằng chứng. `NOT RUN` hoặc lỗi chưa sửa ở ca bắt buộc chặn nghiệm thu. Lượt Planning ghi thiết kế ca test. Kết quả chạy thuộc Development.
